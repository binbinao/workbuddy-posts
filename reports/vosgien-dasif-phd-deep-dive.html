一、核心问题

航空业面临一个根本性断裂：设计（CAD/DMU）和仿真（CAE/BMU）之间存在"数据鸿沟"。

具体表现：

  • DMU（数字样机）只有几何信息，缺乏行为描述
  • 仿真工程师每次都手动从 DMU 提取数据、重建模型、定义接口
  • 设计变更后，仿真模型无法自动追踪和更新
  • 多学科协同仿真时，各合作伙伴使用的工具/数据模型不兼容
  • 没有统一的"接口对象"来描述组件间的物理交互
💡 核心问题

如何让"几何定义"和"行为仿真"在同一数字环境中双向同步？

二、四层概念体系

第 1 层：DMU → DDMU（Derived DMU）

Referential DMU (RDMU) ──结构/形状变换──→ Derived DMU (DDMU) │ │ 完整几何定义 面向仿真的简化几何 面向设计团队 面向分析团队 由 PDM 管理 由 SDM 管理
🔑 关键洞察

同一个产品需要多种"视图"——设计视图、结构分析视图、热分析视图等。DMU 不应只有一个，而应能派生出多个"下游 DMU"，每个适配特定仿真需求。

第 2 层：DMU → BMU（Behavioural Mock-Up）

DMU (几何世界) BMU (行为世界) ├── 几何形状 ├── 仿真模型 ├── 装配结构 ├── 网格模型 ├── 物理接口 ├── 边界条件 └── BOM └── 仿真结果 │ │ └──── DASIF 双向桥 ────────┘

BMU 定义：DMU 的仿真等价物——不仅包含几何，还逻辑链接所有仿真物理行为所需的数据和模型。

第 3 层：DASIF 框架（核心贡献）

┌─────────────────────────────────────────────────────────┐ │ DASIF 框架 │ │ │ │ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ │ │ │系统定义层 │ │拓扑层 │ │配置管理层 │ │ │ │System │ │Topological │ │Config │ │ │ │Definition │ │Layer │ │Management │ │ │ │Layer │ │ │ │Layer │ │ │ │ │ │ │ │ │ │ │ │• 功能制品 │ │• CAD拓扑 │ │• 多视图配置 │ │ │ │• 结构制品 │ │• FE拓扑 │ │• 变更传播 │ │ │ │• 行为制品 │ │• 接口映射 │ │• 效度管理 │ │ │ │• 接口/交互 │ │ │ │ │ │ │ └──────────────┘ └──────────────┘ └──────────────┘ │ │ │ │ 互操作层：PDM/SLM 语义映射 + BDA BOM 标准化交换 │ └─────────────────────────────────────────────────────────┘ ↕ ↕ CAD-DMU 环境 CAE-BMU 环境

DASIF = Design-Analysis System Integration Framework

三大核心能力组合：

  1. PDM 配置管理 — 多视图产品结构、效度(effectivity)、变更传播
  2. MBSE 系统建模 — SysML 扩展、面向对象的接口建模、端口委派
  3. SDM 仿真数据管理 — 仿真意图、建模需求、模型质量

第 4 层：BDA BOM（标准化数据模型）

DASIF 的概念数据模型被贡献给 CRESCENDO 项目的 BDA 平台，形成 BDA Business Object Model——一个标准化的共享数据模型，使异构 PLM/SLM 系统能够互操作。

三、三大关键技术贡献

1. 数字接口建模（Digital Interface Modelling）

这是论文最核心的创新。传统 DMU 只描述几何邻接关系，Vosgien 提出：

Interface = 3 层架构 ├── Design Layer → CAD 特征级接口定义（面、边、坐标系） ├── Behaviour Layer → 物理行为描述（力、热、流边界条件） └── Applicative Layer → 仿真工具特定的接口参数映射
  • 接口通过 Ports（端口）建模，支持层级委派（子组件端口→父组件端口）
  • 接口对象可封装和复用：一次定义，多次仿真使用
  • 支持多物理场：结构、热、流体接口统一建模

2. 多视图 DMU 配置管理

RDMU ──→ Product View 1 (结构分析) ──→ DDMU₁ ──→ BMU₁ │──→ Product View 2 (热分析) ──→ DDMU₂ ──→ BMU₂ │──→ Product View 3 (气动分析) ──→ DDMU₃ ──→ BMU₃ └──→ Product View N (...) ──→ DDMUₙ ──→ BMUₙ

Product View 定义了产品表示与使用/生成该表示的活动之间的链接。每个 Product View 定义了：

  • 适用域（Domain of Validity）
  • 相关仿真意图（Simulation Intent）
  • 所需的结构/形状变换

3. 仿真意图驱动（Simulation Intent）

Simulation Intent → Modelling Requirements → 自动化建模程序 │ │ │ "为什么做仿真" "需要什么精度/抽象级别" "如何自动生成网格/模型"

这一机制使得：

  • 给定仿真意图后，系统自动选择合适的建模要求
  • 建模要求驱动 DMU→DDMU 的变换参数
  • 最终实现 FE 模型的自动装配

4. CAD-CAE 双向可追溯性

CAD Model ←──特征映射──→ System Object ←──特征映射──→ FE Model │ │ │ 几何特征 接口/交互定义 网格特征 (面、边、孔) (端口、连接器) (节点、单元)

每个 FE 模型都可以追溯到其来源 CAD 模型的特征，反之亦然。

七、对工业软件的启示

1. PLM + MBSE 融合是必然趋势

Vosgien 的核心论点：PLM 不仅仅是工具，而是管理复杂 SoS 的策略。MBSE 必须在 PLM 策略中占据核心位置。

当前现实：PDM（管几何）和 SDM（管仿真）是割裂的，而产品是一个整体。

2. 接口建模是关键短板

现有 PLM/CAE 系统缺乏显式的"接口对象"建模能力。接口信息散落在：

  • CAD 的装配约束中（隐含）
  • CAE 的边界条件中（隐含）
  • 工程师的脑中（隐性知识）
🎯 机会

数字化接口 = 显性化工程知识，这是工业软件的机会。

3. 多视图配置管理是刚需

一个产品需要面向不同学科/阶段/精度的多种"视图"，但现有系统只支持单一 BOM 结构。需要：

  • 多视图 BOM 管理
  • 视图间的变更传播
  • 效度（Effectivity）管理

4. 标准化数据模型是互操作基础

BDA BOM 的实践表明：仅依赖 AP233/AP239 不够，需要组合多个 STEP 协议才能覆盖协同仿真场景。

  • AP209 → FE 模型与结果
  • AP233 → SysML 系统建模
  • AP239 → PLCS 产品生命周期支持

5. 仿真自动化仍远未成熟

论文的 Gap Analysis 显示，即使在 CATIA V6 和 Teamcenter 这样的顶级商业平台中：

  • 基于仿真意图的自动建模
  • CAD 特征到仿真参数的自动映射
  • 多学科耦合仿真的接口自动处理

以上能力仍不成熟——仿真自动化存在巨大的工程化空间。
